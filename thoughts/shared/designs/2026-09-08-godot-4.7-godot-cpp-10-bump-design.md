## Problem Statement

We are pinned to a **desynchronized** state: `game/project.godot` claims **Godot 4.5**, but `godot-cpp` is at detached `6388e26` (`godot-4.4-stable-10`) while `.gitmodules` still says `branch = 4.3`.

**Goal:** bump atomically to **Godot 4.7** (`config/features`) + **godot-cpp `10.0.0-rc2`** (`5ed72a0`, first tag with `4.7-beta1` interface), with `api_version=4.7`.

**Why now:** `4.5` is now security-only per release policy. `10.x` is the new versioning line for all `4.x` going forward — `godot-4.5-stable` exists but lacks `4.7` bindings. Building against `4.4` bindings with a `4.7` editor risks `GDExtensionClassCreationInfo` / `ClassDB` hash mismatches.

## Constraints

**Hard constraints — non-negotiable:**

- **No local builds.** All verification must be CI-driven (`builds.yml` 56-job matrix + `fast.yml` single job). Design must fail fast with clear errors if `api_version` is missing.
- **GDExtension ABI must match editor.** `extension_api-4-7.json` + `gdextension_interface.json` (new in 10.x) must be generated, not the old mono `extension_api.json` / `gdextension_interface.h`.
- **Existing scenes/assets must keep loading.** `config_version=5` stays; `PlayerController` / `InputManager` / `HealthComponent` / `TrafficLight` registration must survive `GDREGISTER_CLASS` without source changes.

**Soft constraints:**

- Keep both build systems (SCons primary, CMake secondary) in sync — they share the same `api_version` contract via different variables.
- Minimize churn: one atomic commit, no unrelated refactors.

## Approach

**Chosen: direct tag pin to `10.0.0-rc2` with `api_version=4.7` defaulted in-repo.**

I'm defaulting `api_version` inside `SConstruct` and `CMakeLists.txt` so every invocation (local or CI) works without remembering a CLI flag. CI also passes it explicitly as belt-and-suspenders.

- `SConstruct` passes `api_version="4.7"` via the `SConscript` dict — this is the **required** new contract in `tools/godotcpp.py:552-554` (`UserError: 'api_version' must be provided`).
- `CMakeLists.txt` sets `GODOTCPP_API_VERSION "4.7" CACHE STRING` before `add_subdirectory(godot-cpp SYSTEM)` — mirrors the `FATAL_ERROR` guard at `cmake/godotcpp.cmake:280`.
- Submodule moves from detached `6388e26` to tag `10.0.0-rc2` (`5ed72a0`), `.gitmodules` branch updated to `master` (10.x line).

**Alternatives considered and rejected:**

- **Target `godot-4.5-stable` (`e83fd09`) instead of `10.0.0-rc2`.** Rejected — it pins us to 4.5 bindings and we'd need another bump for 4.7. 10.x already carries 4.7-beta1 interface and is the forward-supported line.
- **Require `api_version=4.7` only on CLI (no in-repo default).** Rejected — every developer and CI job must remember the flag. The `10.0.0-rc2` template recommends in-repo defaulting; forgetting it is a hard `UserError` with no fallback.
- **Bump Godot editor to 4.7 but keep godot-cpp at 4.4.** Rejected — `extension_api.json` header is `4.4`, `gdextension_interface.h` is static; structs like `GDExtensionClassCreationInfo4` evolve, mixing risks memory corruption on `GDREGISTER_CLASS`.

**Effort:** ~1 commit touching 7 files. No `src/` logic changes. Risk is build-break, not runtime.

## Architecture

The bump is a **version-coherence plane** across 4 layers, not a feature change.

**Key insight:** godot-cpp `10.x` fundamentally changes how bindings are sourced — from a checked-in mono `extension_api.json` + `gdextension_interface.h` to **per-version generated** `extension_api-4-7.json` + `gdextension_interface.json` → `gen/include/gdextension_interface.h`. The architecture shifts from "static header" to "generated header via `make_interface_header.py`."

**Layers that must agree:**

- **Source of truth:** `.gitmodules` gitlink SHA + branch
- **Build contract:** `SConstruct` `api_version` dict + `CMakeLists.txt` `GODOTCPP_API_VERSION` cache var → drives `tools/godotcpp.py` / `cmake/godotcpp.cmake` binding generation
- **Runtime manifest:** `game/project.godot` `config/features` + `game/bin/trauma.gdextension` `compatibility_minimum` / `reloadable`
- **CI contract:** `builds.yml` / `fast.yml` scons invocations + `setup-godot-cpp` action version + scons cache keys

No new services, no new abstractions — just aligning 4 existing contracts to `4.7`.

## Data Flow

**Before (4.4 path, stale):**

1. Developer runs `scons target=template_debug platform=linux arch=x86_64` → `SConstruct:38` delegates to `godot-cpp/SConstruct` with no `api_version` → `tools/godotcpp.py` reads mono `gdextension/extension_api.json` (`4.4.0`) + static `gdextension_interface.h` → generates `gen/include/godot_cpp/classes/*` → compiles `SharedLibrary` → copies to `game/bin/linux/`.
2. Godot `4.5` editor loads `game/project.godot` (`features 4.5`) → `dlopen`s `libTRAUMA...so` → calls `trauma_engine_init` → `GDREGISTER_CLASS` via `4.4` bindings.

**After (10.0.0-rc2 + 4.7):**

1. Developer/CI runs `scons ... api_version=4.7` (or relies on SConstruct default) → `SConstruct:38` passes `api_version="4.7"` dict → `godot-cpp/SConstruct:48-49` `cpp_tool.generate(env)` + `env.GodotCPP()` → `_get_api_file()` at `tools/godotcpp.py:552-561` resolves `gdextension/extension_api-4-7.json` → `binding_generator.py` + `make_interface_header.py` generate `gen/include/gdextension_interface.h` + `gen/include/godot_cpp/classes/*` → compile with `HOT_RELOAD_ENABLED` only if `use_hot_reload=true` → `SharedLibrary` → copy to `game/bin/{platform}/`.
2. Godot `4.7` editor loads `game/project.godot` (`features 4.7`) → parses `trauma.gdextension` (`compatibility_minimum 4.7`, `reloadable=true` if enabled) → `dlopen` + `dlsym(trauma_engine_init)` → `trauma_engine_init` at `src/register_types.cpp:40` via `GDExtensionBinding::InitObject` (now with `GDExtensionGodotVersion2` + main-loop callbacks slot, unused) → `initialize_gdextension_types(SCENE)` → `GDREGISTER_CLASS` for 4 classes via `4.7` bindings.
3. **CMake parallel:** `cmake -B build` → `CMakeLists.txt:27` `add_subdirectory(godot-cpp SYSTEM)` with `GODOTCPP_API_VERSION=4.7` → `cmake/godotcpp.cmake:276-284` validates, `GodotCPPModule.cmake:86-125` `binding_generator_generate_bindings` with `gdextension_interface.json` → `gen/include` → `libTRAUMA.*` → copy to `game/bin/`.

**Cache invalidation:** scons cache key at `builds.yml:73/86` includes `4.7` so `4.4` cached `gen/` is not reused.

## Error Handling

**Build-time failures — must be loud and actionable:**

- **Missing `api_version` (SCons):** `tools/godotcpp.py:554` `UserError: 'api_version' must be provided` → `scons` exits 1 before compilation. **Strategy:** default in `SConstruct` + explicit in CI so this never fires; error message is already clear.
- **Missing `GODOTCPP_API_VERSION` (CMake):** `cmake/godotcpp.cmake:280` `FATAL_ERROR "'GODOTCPP_API_VERSION' must be provided"` → `cmake` configure fails. **Strategy:** `CACHE STRING` default before `add_subdirectory`; CI passes `-DGODOTCPP_API_VERSION=4.7`.
- **Wrong submodule SHA / missing `extension_api-4-7.json`:** `binding_generator.py` fails with file-not-found. **Strategy:** atomic commit of `.gitmodules` + gitlink + `SConstruct` so checkout and contract move together; CI checkout with `submodules: true` fetches correct SHA.
- **Stale scons cache:** old `gen/` from `4.4` reused → hash mismatches or missing symbols. **Strategy:** bust cache key (`4.7` suffix) on bump; first CI run cold-builds.
- **Clean checkout without prior `gen/include/gdextension_interface.h`:** `src/register_types.cpp:3` `#include <gdextension_interface.h>` would fail if included directly. **Strategy:** no source change needed — `gen/include` is generated before `src/` compiles via `env.GodotCPP()` dependency; but if anyone includes the old static path, note it is now generated.

**Runtime failures:**

- **`compatibility_minimum` too low:** building against `4.7` bindings but claiming `4.1` → loads on `4.1` editor then `get_proc_address` for `4.7`-only symbols returns `nullptr` → segfault or `init_obj.init()` returns `false` and Godot logs `Unable to load GDExtension`. **Strategy:** bump to `"4.7"` (or `"4.3"` minimum for `10.x` support) so Godot blocks load on too-old editors with a clear version error.
- **Hot-reload silently disabled:** `10.x` defaults `use_hot_reload=false`, so without `reloadable=true` + `use_hot_reload=true` the editor won't attempt live reload and `ClassDB::_recreate_instance_func` is `nullptr`. Not a crash, but confusing. **Strategy:** explicitly decide — either document "hot-reload off by default" or set `use_hot_reload = (target != template_release)` + `reloadable=true` to restore old behavior.
- **Suffix/path mismatch:** `CMakeLists.txt:76` `OUTPUT_NAME "${LIBNAME}${GODOTCPP_SUFFIX}"` and `SConstruct:54` `libTRAUMA{suffix}` must stay in sync with `trauma.gdextension:8-56` paths. Suffix logic unchanged in 10.x (`tools/godotcpp.py:516-525`), so no new risk.

## Testing Strategy

**Constraint: no local builds — all verification is CI-observed.**

- **Fast feedback: `fast.yml` single job** — `scons target=template_debug platform=linux arch=x86_64 precision=single api_version=4.7` must go green. This is the gate before the 56-job matrix. Watch log for `UserError` or `FATAL_ERROR` absence and `gen/include/gdextension_interface.h` generation.
- **Full matrix: `builds.yml` 56 jobs** — `platform` × `arch` × `target-type` × `float-precision` all with `api_version=4.7`. Failures are per-platform; pay attention to `web` (emsdk `USE_PTHREADS`, `nothreads`) and `ios`/`android` (NDK) as the 10.x changelog notes fixes there (`-2147483648` MSVC, `RID` alignment, 32-bit Windows). All 56 must be green; cache keys must be fresh.
- **CMake smoke (manual trigger or follow-up):** if `builds.yml` only covers SCons, trigger a `cmake -DGODOTCPP_API_VERSION=4.7 -B build && cmake --build build` run (can be added as a one-off workflow dispatch). Validates the `GODOTCPP_API_VERSION` contract.
- **Editor smoke (post-merge):** open `game/project.godot` in **Godot 4.7.2** editor — verify `config/features` auto-stays `"4.7"` and project loads without `GDExtension` load errors. Run the game scene once to hit `trauma_engine_init` → `initialize_gdextension_types` → `InputManager::initialize_input_map()` path.
- **Negative test (implicit):** revert `api_version` line locally in a draft PR — CI should fail with the exact `UserError: 'api_version' must be provided` to prove the guard is active. Proves error handling works.
- **Cache validation:** confirm `godot-cache-restore` miss on first run after key bump, then hit on second run (cache save/restore logs).
